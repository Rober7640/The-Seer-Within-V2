# Soulmate Initials Reading — n8n delivery workflow (Job B)

Status: design approved in conversation 2026-10-12 · Rule: product delivery runs on **n8n** (operator,
2026-10-12). The app's job ends at capturing the order (Job A); this workflow writes and sends it.
Template: the **02 Twin Flame** fulfilment (an Evelyn product) —
`improve-v1/v1-one-time-BEs/docs/02/n8n/docs/02/02-fulfilment-OPENAI.n8n.json`, its generator
`02/n8n/scripts/build-02-n8n.py`, and `02/n8n/docs/02/02-HANDOVER.md` (lessons).

## 1. What the buyer gets (the promises this must keep)
From the pitch script (`11-video2-script-draft.md`) and the Job A sales page:
- **Soulmate Initials Reading** — seven cards, one question each:
  1. Who he is · 2. His first initial · 3. His last initial · 4. Someone new or someone she already
  knows · 5. Where they're likely to meet · 6. When · 7. What he's like (and looks like)
  — plus **a picture of her seven-card spread** with what each card means and how it connects to her life.
- **Soulmate portrait**, 1,000+ words: personality, strengths and flaws, loyal / honest / romantic.
- **Bonus 1 — Heart Block Reading**: what's been keeping love at arm's length and how to let it go.
- **Bonus 2 — Past Love Reading**: whether someone from her past is coming back, and whether to let him.
- If she bought the add-on: a short **"Your {stone} has been charged"** page.
- Replies to the delivery email go to the support inbox (answered by hand).

**Format:** one PDF, three parts, each with its own title page; cover with her first name and stone.
**Timing:** delivered **≈ 20 hours after payment** (inside the "within 24 hours" promise).

## 2. Workflow — "Soulmate Initials · delivery"
n8n Cloud (`ezyabsorb.app.n8n.cloud`), core nodes only (Code, HTTP Request, If, Loop, Aggregate,
Wait, NoOp), generated by `build-soulmate-initials-n8n.py` and pushed with the API — never hand-edited.

1. **Webhook** ← Stripe `checkout.session.completed` (its own Stripe webhook endpoint), respond on receipt.
2. **If** `type` + `metadata.product == be_soulmate_initials` + `payment_status == paid`, else NoOp.
3. **Claim** — `POST /api/be/soulmate-initials/claim {sessionId}`; `409` (already claimed/delivered) →
   stop. Fixes the double-send on Stripe retries (02 lesson 7).
4. **Fetch order** — `GET /api/be/soulmate-initials/fulfilment/:sessionId` → email, firstName,
   dateOfBirth, stone, bump, paidAt.
5. **Numbers + draw (Code)** — reuse the 08 Stage-1 Code node logic / `server/lib/numerologyEngine.ts`:
   Life Path (birth date), First-Name number (Pythagorean), Personal Year. Seven-card draw **seeded
   from the session id** (FNV hash → xorshift shuffle), so a retry gets the same cards.
6. **Initials (Code)** — Pythagorean groups (1 AJS · 2 BKT · 3 CLU · 4 DMV · 5 ENW · 6 FOX · 7 GPY ·
   8 HQZ · 9 IR). First initial from the Life Path group, last initial from the First-Name-number
   group; inside a group pick by a **seeded, frequency-weighted** choice from letters that commonly start
   US men's first names / surnames (two frequency tables in the generator, from US census/SSA name
   data); a letter that starts **under 1%** of those names is never chosen (this rules out Q, X, Z, U, Y
   among others); a group left empty falls back to the next group up (9 → 1). Same order → same
   initials, always. The letters are passed to the writer as facts, never invented by the model.
7. **Write (loop over the 7 cards)** — OpenAI chat completions (as 02: `gpt-5.6-terra`,
   `reasoning_effort: medium`), system = Evelyn voice profile (from 02), user = per-card prompt with
   the card, position question, her numbers, the initials, stone. Keep prose; throw on empty/truncated;
   one retry per card.
8. **Join** → one flowing letter (connected speech, no lists). Then **portrait**, **Heart Block** and
   **Past Love** calls (each grounded in the same draw and numbers), and the add-on page if `bump`.
9. **Grade** — a second model pass with a rubric: initials stated exactly as given · all 7 positions
   answered · portrait ≥ 1,000 words · both bonuses present · no health/legal/financial advice · no
   guarantees of outcome · no worked-example copy. Fail → regenerate once with the same draw, then
   send anyway and log the failure (`POST /grade-log`), as 02.
10. **Render (Code → PDFShift)** — HTML with `@page` CSS, Georgia serif, cover, a **spread image** built
    from the card JPGs on S3 (`evelyn/tarot-rws/<card>.jpg`, looked up from the draw, never from model
    text), three part title pages. PDFShift → PDF (check every image URL is public first — PDFShift
    silently drops 403s).
11. **Store** — Supabase Storage (private bucket `analysis_pdf/soulmate-initials/<sessionId>/…`);
    signed URL valid 1 year.
12. **Wait** until `paidAt + 20h`.
13. **Send via AWeber** — find the subscriber on the product list → PATCH tag
    `be-soulmate-initials-delivered` + `custom_fields.reading_url` (**re-send every custom field** —
    AWeber's write replaces them all). An AWeber campaign on that tag sends Evelyn's email with the link;
    reply-to = support inbox.
14. **Mark delivered** — `POST /api/be/soulmate-initials/delivered {sessionId, readingUrl, readingBody}`
    (camelCase — 02 had a snake_case bug).

**Error alerts:** an **Error Trigger** workflow (set as this workflow's `errorWorkflow`) emails the
support inbox: order id, failed node, link to the execution. **Watchdog:** a daily schedule calls
`GET /api/be/soulmate-initials/undelivered?olderThanHours=22` and emails any orders paid but not
delivered.

## 4. Setup the operator must do (cannot be done by API)
- Arm the webhook **from the n8n UI** (API activation doesn't register it — 02 lesson 1).
- Add a Stripe webhook endpoint → the n8n webhook URL, event `checkout.session.completed`.
- AWeber: create the product list (or tag) and the "Your reading is ready" campaign triggered by
  `be-soulmate-initials-delivered`, from Evelyn, reply-to support.
- Confirm the Supabase bucket behind the storage credential (known blocker in 02's test drives).
- An SMTP (or Gmail) credential in n8n for the alert emails to the support inbox.

  tag → email received → `delivered` recorded; a forced failure triggers the alert email.
