# /fb Upsell 2 copy: today (A) vs the bracelet is a magnet (B) · `v1_fb_u2_copy_2026`

Built 2026-11-27 on `prod/fb-upsell` (on top of f1fb8d4, the Upsell 1 copy test). Uncommitted, for review.

## What
- **A (control, `{}`)** is today's Upsell 2 script, `V1_UPSELL2`, byte for byte. An A buyer gets no copy override at all, and her AI beats use today's prompts, unchanged.
- **B (`{"copy":"magnet"}`)** is "hook M, the magnet". The approved script is in [`2026-11-27-v1-fb-u2-copy-2026-hook-M-magnet.md`](2026-11-27-v1-fb-u2-copy-2026-hook-M-magnet.md). It is built in `client/src/lib/upsellCopy/fbU2Magnet.ts`, and its test parses that file and checks every line against it, for all four topics and both RITUAL lines.
- Copy only. The price ($47, $30 downsell), charge, stage order (`V1_CHAIN_2`), bracelet photo, shipping form and success page are the same in both arms.
- **What B changes:**
  - Every stage's bubbles. Money and purpose swap the lines OTHER TOPICS lists; someone keeps the love lines and changes only Q2 (`{personName}`, or "them" when no name is on file).
  - Its own Q1, Q2 and Q3, buttons, AFTER branches and typed-answer matching (NOTES FOR BUILD, in its check order). A typed "no" never takes a yes branch.
  - The two AI beats use their own prompts (`buildManifestRevealMagnetPrompt`, `buildManifestPersonalizeMagnetPrompt`), written from the script's two [AI:] lines, with no quoted sample lines. The server drops a reply that breaks a ban (a banned word, a dash, "you know", a "magnetic" stone). On any failure the page plays the script's own fallback line, never the generic "energy" lines.
  - The accept button, and her reply bubble when she taps it, read "Yes, set my bracelet tonight".
  - A $47 buyer gets one extra SUCCESS bubble after bubble 1: "I'll set it tonight, during your clearing." A $30 downsell buyer does not.
  - RITUAL_INSTRUCTION bubble 2 names "the candle that bent at your name" only for a buyer who saw it in /fb chat B. Everyone else gets "While I'm doing your clearing, I'll set your bracelet on my altar."

## Who's in
The server reads it all off her order row. Nothing comes from the client.

| Rule | Read from |
|---|---|
| /fb only | `conversations.price_variant` carries `_fb` (`funnelParamFromPriceVariant`). This also keeps out /fb-tarot retarget orders (`v1-tarot`, or no variant); the client doesn't ask for a retarget order either |
| No belief lane | `conversations.lane IS NULL` |
| A known topic | `bucket` is one of love / money / purpose / someone |
| Both paths | path A (bought Upsell 1) and path B (declined it), from `upsell_purchased` |
| Both chat-flow arms, both Upsell 1 copy arms | not filtered |
| No price rule | Upsell 2 is $47 / $30 at every V1 charge site (`/api/upsell2/charge`, the hosted fallback checkout, `upsell2Cents()` for Payments.AI). No experiment or price variant moves it. Only the backend offers' `be_bracelet` has its own price, and those pages never ask for this test |

Backend offer pages (02 and the rest) keep their own Upsell 2 copy and never call the test.

## Key, subject, tally
| | |
|---|---|
| Key | `v1_fb_u2_copy_2026`, A 50 / B 50, scope funnel `v1-fb` |
| Subject | the normalised email, as the Upsell 1 test: bucketed on `email.trim().toLowerCase()`, exposure on `hashEmail(email)` |
| Assigned | `GET /api/fb/u2-copy?session_id=…`, called when the Upsell 2 chat starts, before the first bubble. The exposure (surface `upsell2_chat_start`, context `{conversationId, funnel, path, topic, candle}`) is logged in the same call. `candle` is true only for a B buyer shown the candle line |
| AI beats | the page adds `copy: "magnet"` to its `/api/upsell2/reading` request only in arm B. Without it the endpoint runs today's prompts |
| Failure | Any failure answers A: bad id, no row, ineligible, draft or off test, DB error. So does a reply that takes more than 2s |
| Tally | conversion `upsell2_funnel` → `tallyUpsell2`. Per arm: exposures, buyers (`upsell2_purchased`), revenue (`upsell2_amount`, so a $30 downsell counts at $30), revenue per exposure, $47 vs $30 buyers, each split by path A / B. The admin guard allows only this key |
| Size | `targetN` 300 per arm. The draft SQL has a read-only count of today's take rate by path (0d) and a rule of thumb |

The dashboard shows the usual per-arm table plus an "Upsell 2 by price and path" table.

**Known edge (same as Upsell 1):** conversations are reused per email and the upsell2 flags are never reset, so someone who bought the bracelet on an earlier order reads as a buyer. There is no Upsell 2 payment timestamp to separate them. It's roughly the same in both arms.

## Preview

- `?demo=true&u2copy=magnet`: B, with the altar line.
- `?demo=true&u2copy=magnet&chatflow=b`: B, with the candle line.
- `?u2copy=today`: forces A.
- On a real test order, add `&u2copy=magnet` to its `session_id` link.

## Turn it on
1. Merge and deploy. Without the row, the code is inert: `/api/fb/u2-copy` answers A for everyone.
2. Walk B with the preview links.
3. Run `improve-v1/create-fb-u2-copy-experiment-2026-11-27.sql`. It creates a **draft**, still inert.
4. Press Start in `/admin/experiments`.

## Code
- `client/src/lib/upsellCopy/fbU2Magnet.ts`: arm B's copy, built from `{bucket, candle}`, and its typed-answer matching.
- `client/src/lib/upsellCopy/questions.ts`: Upsell 2's Q1, Q2, Q3 and typed-answer matching now come from the copy. When the copy sets none, they fall back to the shared V1 constants.
- `client/src/lib/upsellCopy/upsell2Fields.ts`: today's accept text, AI fallback lines, the $47 success extra, and the reading request, with arm B's fields applied on top.
- `client/src/lib/fbU2Copy.ts`: the client call (2s timeout, falls back to A) and the preview switch. `client/src/pages/Upsell2Page.tsx` waits for it before the first bubble.
- `server/lib/fbU2Copy.ts`: eligibility, and the one call that assigns, logs and answers. The route is in `server/routes.ts`.
- `server/lib/prompts.ts`: the two magnet prompts and `magnetReplyProblem`. `server/lib/claude.ts`: `generateManifestRevealMagnet` and `generateManifestPersonalizeMagnet`.
- `server/lib/experiments.ts`: `resolveFbU2Copy`, `assembleUpsell2Funnel` and `tallyUpsell2`. `server/routes/admin/experiments.ts`: the `upsell2_funnel` guard and results. `client/src/components/admin/Upsell2FunnelPanel.tsx`: the dashboard table.
