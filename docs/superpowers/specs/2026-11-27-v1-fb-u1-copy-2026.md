# /fb Upsell 1 copy: today (A) vs the stone is a filter (B) · `v1_fb_u1_copy_2026`

Built 2026-11-27 on `prod/fb-upsell` (cut from origin/Production 3c0deb8). Uncommitted, for review.

## What
- **A (control, `{}`)** is today's Upsell 1 script, `V1_UPSELL1`, byte for byte. An A buyer gets no copy override at all.
- **B (`{"copy":"filter"}`)** is "hook 6, the stone is a filter". The approved script is in [`2026-11-27-v1-fb-u1-copy-2026-hook-6-filter.md`](2026-11-27-v1-fb-u1-copy-2026-hook-6-filter.md). It is built in `client/src/lib/upsellCopy/fbU1Filter.ts`, and its test checks every line against that file.
- Copy only. The price, charge, stage order (`V1_CHAIN_1`), stone photo, shipping form and Upsell 2 are the same in both arms.
- **What B changes:**
  - All of B's three questions, buttons and AFTER branches.
  - Three topic spots: GAP bubble 4, FEEL bubble 4 and BUCKET.
  - The accept button reads "Yes, set my stone tonight".
  - RITUAL bubble 2 names "the candle that bent at your name" only for a buyer who saw it in /fb chat B. Everyone else gets "I set your stone on my altar."

## Who's in
The server reads it all off her order row. Nothing comes from the client.

| Rule | Read from |
|---|---|
| /fb only | `conversations.price_variant` carries `_fb` (`funnelParamFromPriceVariant`) |
| No belief lane | `conversations.lane IS NULL` |
| $47 only | `conversations.upsell1_amount_cents = 4700`. The operator is stopping `u1_price_2026` (2026-11-27) to focus on $47; stopped or concluded A, every /fb lead falls back to $47, so everyone is in. Never conclude it B or C |
| A known topic | `bucket` is one of love / money / purpose / someone |
| Both chat-flow arms | not filtered |

## Key, subject, tally
| | |
|---|---|
| Key | `v1_fb_u1_copy_2026`, A 50 / B 50, scope funnel `v1-fb` |

| Tally | conversion `upsell1_funnel` → `tallyUpsell1`. Denominator = offered, buyer = `upsell_purchased`, revenue = `upsell_amount`. The admin guard now allows this key; its arms carry no price |
| Size | `targetN` is not set yet. It needs /fb's real U1 take rate at $47; the draft SQL has a read-only count and a rule of thumb |

## Preview
On `/fb/welcome1`. It forces B, never calls the server and is never counted.
- `?demo=true&u1copy=filter`: B, with the altar line.
- `?demo=true&u1copy=filter&chatflow=b`: B, with the candle line.
- `?u1copy=today`: forces A.
- On a real test order, add `&u1copy=filter` to its `session_id` link.

## Turn it on
1. Merge and deploy. Without the row, the code is inert: `/api/fb/u1-copy` answers A for everyone.
2. Walk B with the preview links.
3. Run `improve-v1/create-fb-u1-copy-experiment-2026-11-27.sql`. It creates a **draft**, still inert.
4. Set `targetN`, then press Start in `/admin/experiments`.

## Code
- `client/src/lib/upsellCopy/fbU1Filter.ts`: arm B's copy and typed-answer matching.
