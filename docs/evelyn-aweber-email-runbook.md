# Technical appendix (Robert)

Context for the person checking results — not needed by the AWeber team.

### Why no deploy is needed
The lander already parses and stores every URL param above:
- `server/routes/evelynLander.ts:42-51` — validates `email`, `token`/`t`, `bucket`, `src`, `campaign`.
- `server/routes/evelynLander.ts:107-116` — resolves `email` → returning-user segment.
- `client/src/pages/EvelynLanderPage.tsx:83-90, 221-225` — reads them from the URL and forwards to the backend.
- `server/lib/evelynLanderEngine.ts:81-116` — `bucket` selects the opener; `:158-160` feeds it to the AI as context.

So this closes PRD tasks **1.3** (link tagging) and **1.4** (email/bucket recognition) with **zero code** — they were
already built. **1.2** is the copy A/B above. A magic `token` is intentionally not passed (AWeber doesn't hold our
per-subscriber tokens); `email=` is the recognition mechanism.

### Verification query (app DB)
Run a few days after a tagged send. Confirms params are landing and shows engagement lift by arm.

```sql
-- Coverage + engagement by campaign arm, last 3 days
SELECT
  src,
  campaign,
  bucket,
  count(*)                                                   AS sessions,
  count(*) FILTER (WHERE resolved_segment <> 'brand_new')    AS recognized,   -- email= working
  round(100.0 * count(*) FILTER (WHERE turn_count >= 1) / count(*), 1) AS pct_engaged,
  count(*) FILTER (WHERE cta_clicked)                         AS cta_clicks,
  count(*) FILTER (WHERE resolved_user_id IS NOT NULL)        AS registered
FROM evelyn_lander_sessions
WHERE started_at >= now() - interval '3 days'
GROUP BY src, campaign, bucket
ORDER BY sessions DESC;
```

**What "working" looks like:**
- `src='aweber'` now covers ~all of the send's sessions (was ~2.4%).
- `recognized` is a meaningful share (email resolution firing) instead of ~0.
- Arm **B** `pct_engaged` should beat arm **A** (the 1.2 hypothesis). Baseline Evelyn open-box ≈ 17.5%;
  Luna's warm-email open-box ≈ 40.5% is the ceiling to chase.

Measure from the app DB, not PostHog (PostHog logs only a fraction of these sessions).
